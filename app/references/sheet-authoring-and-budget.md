# 共用分支：多格母图、帧数与内存预算

轻量萌宠与复杂人物共用。本文件处理**怎么少调用、怎么排格、怎么切、怎么不把运行内存撑大**；不替代各体型的动作设计。

## 优先考虑一张母图，而不是每帧一张请求

用户所指的典型布局是**行＝方向，列＝动作阶段**。例如5行×4列表示5个独立方向，每方向4张关键姿态，不是一个方向20帧。画面里所有格都放完整人物，方向内保持相同镜头；同一列尽量对应同一解剖相位，便于跨方向切换。另一个合法布局是单方向8／16帧按时间顺序换行，必须显式记录cell→direction／phase映射，不能同时猜两种顺序。

多格图可以减少请求次数、共用身份参考，也可能改善同批画风一致性；**不保证一次出图正确，也不保证总费用按调用次数同比降低**。实际输出尺寸、服务计费、重试率、有效格率共同决定成本；工具未披露模型／价格时不编造金额。实际失败例中，早期四格稿曾把相反步画成相同近侧手臂；后续单格修复成功，不代表多格路线不可用或已经稳定。

先规划整张母图，只有以下原因才拆批：每格像素不足、尾／裙／武器越格、姿态重复／方向漂移、相位数量太多导致指令失效，或单格损坏导致整页重画代价更大。简单小短腿轮廓可先尝试多方向多相位同页；精细长裙可先单方向一页或少量连续相位一页。不是强制所有宠物都20格，也不是强制所有人物都一格一请求。

## 布局合同

生成前创建机器可读布局，至少含sheet ID、拟定实际像素、rows/columns、每格rect、方向／相位、身体轴、地面线和独特帧ID。配一张布局／骨架参考图时，明确辅助线、编号、红蓝不进入正式人物。需要的总体宽高由格大小和留白推导，不能只写“20个小人”。

```text
sheetWidth  = 2*outerMarginX + columns*cellWidth  + (columns-1)*gutterX
sheetHeight = 2*outerMarginY + rows*cellHeight + (rows-1)*gutterY
```

- 每格使用相同角色单位尺度；内部留白根据动作最大伸展设计，身体轴相对格固定，衣摆／尾巴宽不能把人物挤小或挪中线。
- 前后左右运动范围都留余量。生成母图的gutter用于防串格，运行时图集的padding/extrusion用于采样边缘，二者不是同一件事。留白也占整页分辨率，不能无限加大后期待每格仍清晰。
- 先预算**每格实际可用像素**。若返回图只有1024px宽，4列每格不足256px（还没扣留白）；不能当成4张1024px母版。仅请求更大数字不证明工具真的按该尺寸返回。
- 生成后看真实尺寸、行列与单格边界。确认无越格和邻格碎片，再按真实sourceRect提取；不得盲按名义等分裁掉手、尾、裙角。可先用低成本布局小样验证，不把小样质量当成完成品。
- 保存原整页，导出格记录同一个source hash与各自rect；逐格通过／待修／拒绝独立记录。修坏格可返回完整页，但只采用目标完整姿态，其余仍取旧源页；不顺带替换已通过的格。
- 镜像方向只有在身份、饰物与惯用肢体规则允许时复用同一纹理。5个源方向映射8个显示方向不代表无需核查镜像，也不自动增加独特姿态数。

## 多格提示词骨架

```text
输出一张完整角色动画母图，{rows}行×{columns}列，每格完整角色。
参考A决定身份、比例、画风、衣装与固定相机；参考B仅决定各格姿态；参考C仅决定排布。
行顺序={方向列表}，列顺序={相位列表}；格ID与支撑／摆动表={当前批次表}。
同一行不得转镜头；同一相位左右肢体身份跨方向保持。
每格画布={尺寸/比例}，角色身体轴={相对位置}，承重地面={相对位置}。
全组相同身体尺度，保留{既定相位起伏}；按{最大衣裙/尾/器物伸展}留内部安全区和格间空白。
{体型分支中的必要动作/布料约束}。
不要把说明文字、格线或骨架颜色画进角色；背景按实际透明生产流程。
禁止把相反步复制成同一侧；逐格绘制指定的独特姿态，不用全身平移代替。
```

一次生成2／4／8／20格是生产批次，不是最终动作帧数。已验证关键帧后，可以每批补4／8张过渡；最终16或24张来自多批通过的实际独特姿态，而非机械复制一张大图。记录调用数、生成格数、采用格数、重试格数；有计费结果才记实际金额。

## 制作母图和运行图集分开

| 层 | 保留内容 | 加载方式 |
| --- | --- | --- |
| 制作母图 | 高分辨率整页、单格修订、参考、提示词 | 编辑／审图时使用，默认不随游戏常驻 |
| 规范完整帧 | 共同逻辑画布、中心和接触标记 | 用于验证与重建，不必与atlas同时全部解码 |
| 运行图集 | 目标显示尺寸、有限padding、rect、pivot/trim offset | 按角色、动作或方向组加载，可共用镜像纹理 |
| 预览动图 | 用于审阅的WebP／其他容器 | 不当作GPU显存大小的测量依据 |

按实际显示尺寸先做清晰度样板，例如288×384与576×768比较；不未经审图就把所有人物砍半。宽高都减半，RGBA基础像素占用变为四分之一。渲染镜像可共享纹理，提前存两份镜像PNG则仍占资源。重复播放同一帧可以只引用一次，不能把重复引用算独特帧。

紧凑打包可以省掉透明空白，但必须保留统一逻辑画布、pivot和trim offset，运行时恢复位置；不能重新用紧bbox居中。`motion_tool`仍使用规则格图集，公共配准工具仍输出完整画布；新增[共用导出器](asset-layout-and-export.md)在交付层支持透明trim、精确相同图块复用、受限多页打包、PNG／WebP编码和统一目标尺度，并报告实际文件字节及页RGBA估计。它不改制作源图，也不宣称已实现GPU块压缩、镜像纹理复用或宿主流式加载；这些仍需原生能力和实际测量。

## 内存估算

对RGBA8未压缩像素，单份基础像素面：

```text
frameBytes = width * height * 4
allFrameBytes = frameBytes * uniqueFrames * storedDirections * actions * outfits
```

若按每个方向／动作／衣装一个图集，实际分配按**整页尺寸**计算，含空格、padding和浪费，不只加可见角色面积。RGBA8的透明像素也占该纹理存储。合成一张大图能减少文件／纹理数量，不自动减少像素总量；图集留白多时反而更大。

PNG/WebP文件KB不是解码内存。CPU解码副本、GPU纹理、预览canvas、临时生图对象可能各自占用，不能默认只有一份，也不虚报固定副本数。开启完整mipmap通常要额外预算，粗估基础纹理的约1/3；纹理压缩后的占用取决于实际格式、块尺寸、alpha和设备支持，未经验证不写固定压缩比。

`storedDirections`统计独立存储方向（镜像共用不重复），`residentDirections`等统计同时加载的子集。按需加载／预取／释放、按动作或方向分图集、限制同屏角色工作集，能控制峰值。把所有角色的所有动作衣装一次解码，即使只显示当前一帧也可能占满内存。释放逻辑和缓存预算要由真实宿主落实并测量，技能预算工具不等于已经完成运行时优化。

可复用预算命令（不调用生图、不改运行时）：

```sh
python3 scripts/sprite_budget.py --width 288 --height 384 --frames 8,16,24 --directions 5 --resident-directions 1 --actions 1 --outfits 1 --columns 4 --padding 2
```

输出分别列独特帧像素、含padding和空格的图集、全库与当前驻留、可选mipmap及CPU副本估计，并提示页尺寸超限。数值是规划假设，不是实测RSS／显存；最终上真实设备看峰值和换方向卡顿。

以**单个走路动作、5个独立方向、1套衣装、RGBA8单份基础像素、不含图集留白／mipmap／额外副本**为例：

| 每帧尺寸 | 每方向帧数 | 单方向MiB | 5方向全部MiB |
| --- | ---: | ---: | ---: |
| 576×768 | 8 / 16 / 24 | 13.50 / 27.00 / 40.50 | 67.50 / 135.00 / 202.50 |
| 288×384 | 8 / 16 / 24 | 3.375 / 6.75 / 10.125 | 16.875 / 33.75 / 50.625 |

动作与衣装数继续相乘；同屏实例能否共享同一纹理取决于宿主，不把每个实例都机械复制整套图片。建议同时记录源制作尺寸、目标运行尺寸、独特帧数、周期、存储方向、同时驻留动作／方向／衣装、图集页、实际加载／卸载证据。
