# 增量生图与任意方向扩展

用户可以临时提出任何新状态、动作、方向或过渡。技能应从上次可信结果继续，而不是重新猜角色、要求填写固定菜单，或把所有方向全部重画。

## 延续记录

优先读取工程已有的角色／美术记录。新任务没有格式时，可在任务目录维护类似以下的`motion-plan.json`；它是制作索引，不是游戏存档，也不是必须严格照搬的装配schema。

```json
{
  "character": {"id": "actor-a", "identity_reference": "masters/identity.png"},
  "identity_lock": ["左手持剑", "披肩在角色自身右肩"],
  "style_reference": "masters/style.png",
  "camera": {"projection": "沿用现有镜头", "direction_basis": "屏幕上方为N"},
  "scale_contract": {"reference": "masters/neutral.png", "notes": "所有动作保持角色身高单位"},
  "clips": [
    {
      "id": "walk-nw-default",
      "action": "walk",
      "direction": "NW",
      "appearance": "default",
      "status": "accepted",
      "sources": ["masters/walk-nw.png"],
      "timing": "motion.json:default.walk-nw",
      "evidence": "review/walk-nw.html",
      "notes": "用户确认的当前版本"
    }
  ],
  "requested_delta": [{"action": "turn-jump-land", "direction": "NW", "appearance": "default"}]
}
```

实际身份、镜头和方向基准来自项目或本轮假设，不能复制示例的左手剑／披肩／西北。状态区分`planned`、`draft`、`verified`与用户明确的`accepted`；工具通过不能自动升级成用户认可。附源hash、实际返回尺寸、参考角色、选帧、变换、时长、修复原因及回退版本，避免下次从失败试图或旧缓存继续。

动作名是任意稳定ID；既可分`jump-start / airborne-turn / land`，也可先交付连贯的完整短片。方向、外观和动作各自独立；不要要求每个新动作都有全部方向或所有衣装。

## 一个临时请求怎样落地

例如“加东北方向蹦跳”只表示本轮增量，不授权重画其余动作：

1. 从现有记录继承身份、画风、投影、角色单位、东北朝向约定及可用源参考。
2. 将请求定位为`action=蹦跳, direction=NE, appearance=当前外观`；定义起跳、空中、落地等真正需要的阶段。若已有兼容起跳或落地，比较接缝后复用，而不是机械复制。
3. 选择最近的有效姿态参考。原方向提供动作相位／支撑逻辑，新方向提供镜头与遮挡；不能让旧参考继续决定新方向，画出来仍朝原方向。
4. 用AI生成本次独特完整姿态；先看代表性接触与最大伸展，再补真正欠缺的中间姿态。缺帧就补那个运动区间；近似姿态停顿先改时序。完成当前已授权范围，不每生成一张就停下来问用户。
5. 共同单位配准，保持有意的重心与腾空；检查方向、武器手别、支撑／道具、首尾及前后动作接缝。
6. 更新该clip的源图、采用帧、时序、状态和预览；旧clip不被覆盖。只有本次修复要求改变既有共用约束时才扩大检查。

当真正缺少关键身份参考或方向基准存在无法合理推断的冲突时，问一个具体问题，同时完成不依赖该答案的工作。普通未定义装饰、动作幅度或低风险预览默认可作明确提案，不重新索取整份需求。

## 八方向不是横移八次

先记录方向与镜头的对应，常见N/NE/E/SE/S/SW/W/NW只是命名示例。角色面向、移动方向与攻击／投射方向可以不同；按项目实际状态关系制作，不能全部混成一个`direction`。

八方向行走需要在各方向保持相同身份、世界身体尺度和步态相位，同时重画透视、肢体前后关系与可见背面。单侧包、单眼、惯用手和武器不能默认镜像。已明确对称并获准的素材才可镜像复用。

复合动作应把方向拆开记，例如：

```json
{
  "travel": "NW",
  "body_facing": "NW",
  "gaze_by_phase": {"takeoff": "NW", "airborne_turn": "回看方向，按本轮提案确认", "land": "NW"}
}
```

这个例子不是要求回看时把整个身体或移动轨迹翻向相反方向。若身体也翻转，另列阶段中的body_facing；身份的左手剑、披肩侧别仍是角色自身解剖方向。取景相机位置不随着每次回头任意切换。

先选择能暴露问题的几个方向／接触关键姿态验证，再自主完成用户所需矩阵；不是强制每次都从正侧背重新开始。已认可的方向不因扩展而改变。

## 动作状态不限于名称

表情、呼吸、回头、蓄力、滑翔、翻滚、受击、待机小动作、器物互动都能成为clip。动作意图决定身体哪些部分应该动；并非完整帧就要全身大动，也不能用一张静图整体上下漂移来假装新动作。

循环、一次性、持续中段和过渡可组合成新状态流程。记录触发／退出意图及起止姿态；现实游戏里何时切换、是否消耗资源，仍由已有宿主负责。只要求动图时不擅自扩展成玩法、提醒服务或宠物安装。

## 提示词随增量变化

每次只带入本轮相关的身份／画风参考、相邻可信姿态、当前方向和接触约束，明确各参考权威。保留失败原因，但不把所有历史反例堆成越来越长的否定词。先定位根因，再改变一个相关因素；请求、返回、采用和拒绝分别记录。

若用户只要求给未来执行的提示词／技能，本轮交付可复用方法与工具；若用户要求实际生成动作，应调用生图并交付实际能播放的素材，不能只返回这个制作方案。
