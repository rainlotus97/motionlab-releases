# 可保存的骨骼抽样方案

在完整人物生图前，用户希望自己挑帧、预演、保存方案时使用。复用同一`motion_studio.py`服务的`/sampling.html`，不为每个角色重写选帧器。原始连续动作是只读基线；自定义方案保存在项目内，和人物图调帧草稿分开。

## 配置与使用

在已有`studio.project.json`添加实际来源，路径均相对该文件，不能越出项目目录或通过符号链接逃逸：

```json
"sampling": {
  "store": "sampling-plans.json",
  "sources": [
    {"id":"walk-source","name":"原步行","type":"100style","path":"walk-study/motion-data.json"}
  ],
  "libraries": ["motion-library/library.json"]
}
```

支持已有100STYLE归一化数据和本技能Quaternius动作库合同，不是通用FBX/BVH导入器。骨架位置适配为原地动作，保留原根高度；库中的水平rootPath只扣除一次。短腿、圆身与四足只列出该来源实际具有的身体档案。

用户在工作台选动作、身体档案、相机，然后复制原版或建立4／8／16／24帧方案；可增删、调整帧位和停留时长，查看原始连续与离散抽样两种播放。保存只写项目方案；点击采用才更新`selectedPlanId`。新增、复制与保存均不隐式采用，也不触发生图。删除采用中的方案会清除采用状态。原版连续不可覆盖或删除。

## 对称与连续性

循环的默认偶数预设按真实时间取`φ=i/count`，满足第`i+count/2`帧比第`i`帧晚半周期。不把取整后的索引叫精确对称：81段周期的8帧索引含10.125、20.25、40.5等，必须保留小数及插值贡献。终点相位1不再额外停留。非循环动作按完整区间采样并保留终帧，不用半周期对称去认证攻击或跳跃。

`phaseAudit`区分半周期配对、一个正向周期、各段及末→首时间、实际对侧关节偏差。时间成对不等于源动作左右等幅，更不等于人物图已正确；源动作不平衡或边界有断点时，先明确来源问题，必要时提供已有闭合动作作为具名候选。不得静默换来源、镜像肢体、倒放半周期或复制首帧掩盖问题。

首尾慢放只播放一次尾部→开头片段，进入最后待审姿态时暂停，两侧定位同一源姿态；再次观看需点“重播首尾片段”。不要把审查片段末端自动跳回尾部制造的跳转当成真实动作衔接，也不要把工具的审查暂停当作原动作停顿。正常整周期播放与片段审查分开。

摆臂端点自然减速，两个姿态接近不能单凭距离判错。结合相位时间、腕相对肩、踝相对髋、前后极值、支撑交接和末→首方向判断。手选可不对称，但应显示实际误差；不要为通过检查自动偷偷改用户的帧位。

## 会话继续生成

用户说“按选定方案生成”时，先读取项目方案，不能重新均匀抽一套、自动扩帧或改时长：

```sh
python3 scripts/sampling_plans.py inspect --project /project/character/studio.project.json
python3 scripts/sampling_plans.py export --project /project/character/studio.project.json --out /project/character/selected-sampling.json
```

无`--plan`时只导出明确采用的方案；无采用则报错，不猜第一份草稿。用户明确指定方案ID时可用`--plan ID`导出。输出为新文件，拒绝覆盖；来源hash变化时拒绝导出／采用，先重新预演建立有效副本。

导出契约`kind: character-motion-sampling-plan`含项目、计划ID／revision、来源hash／许可、身体档案、相机、解剖身份、选帧顺序、停留时长和完整骨架姿态。`samples`记录源时间／相位；插值样本的`sourceFrameId`为null，`contributors`列真实源帧ID与权重。不能将小数索引伪称某个真实捕获帧。

用同一套绘制器输出姿态参考，不临时另画骨架：

```sh
python3 scripts/render_sampling_guide.py --project /project/character/studio.project.json --out /project/character/new-pose-guide
```

默认仍只读取采用方案；显式`--plan ID`可查看草稿，元数据会标明未采用。输出目录必须全新，包含固定432×768格的4列`guide.png`、独立`pose-XX.png`与`guide.json`。所有格以完整来源共同拟合相机、比例、身体轴和地面，保留实际sourceRect及contributors；不会逐格拉满。这里是骨架技术参考，没有推断裙内支撑或证明人物比例匹配。作为生图参考时先核对与浏览器同相位，再以角色立绘约束身体与衣装。

将这份契约与姿态参考图作为姿态权威，人物原立绘作为外观权威，按复杂或简洁分支规划多格母图。记录生成批次使用的计划ID、revision及文件hash。输出图仍须核对腕、足、衣发及遮挡，再做共用高度／身体轴／承重地面配准；准确抽样不会让生图自动遵守骨架。选定动作方案、人物关键帧、最终流畅度分别验收。

生成后将这份导出JSON作为冻结`planContract`，以明确的`slot → artFrameId / artStepSlot`映射接入[共享逐帧对比](studio-workbench.md#冻结方案与人物逐帧对照)。不要在打开页面时重新导出当前方案替换历史目标；源小数索引、原生帧贡献与人物文件编号分别显示。目标叠加只提供对照，人工记录需要修正的手腕、鞋位、裙摆及衔接，再实际重绘授权范围的完整母版。hash通过不是姿态通过。

更换动作来源也意味着目标姿态变化。例如旧人物按100STYLE绘制，新抽样选UAL `Walk_Loop`，即使都为E向八格、同周期，也不能换编号或只改来源字段就称匹配。旧图可按`metadata.relationship:"historical-unmatched"`放在新目标旁定位问题；按新冻结目标修正实际人物图后，再创建待审候选及逐格记录。保持身份与衣装不等于保留旧动作，不能静默混用旧骨架姿态和新方案时序。

当前预览的小数取样对关节位置做线性插值，不是旋转FK／IK，不保证严格骨长或足锁。高精度骨长／接触要求应在明确转换器中处理后另建来源，不能在提示词中宣称硬约束。导出只生成姿态数据，不自动消耗生图费用或接正式游戏。
