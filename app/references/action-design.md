# 动作设计与连续性

在设计新动作、改角色身体结构、重做移动或战斗时读取。先决定动作怎样发生，再决定图集怎样排；下列动作是可扩展的例子，不是固定状态目录。

## 一张动作卡

把自然语言需求整理成可执行的动作卡，缺省值可由场景推断：

- **意图与结果**：玩家应看懂什么；循环、一次性动作，还是从 A 到 B 的过渡。
- **身体与视角**：两足、四足、无足或特殊结构；朝向、镜头、透视、实际显示尺寸。
- **阶段**：准备 → 发力/执行 → 结果 → 恢复；不需要的阶段可以省略。
- **接触**：各阶段谁承重、何时离地/落地；爪、手、口与道具何时接触或释放。
- **位移**：原地播放或带根位移；移动距离由图像、运行时还是既有动画系统负责。
- **节奏**：主要姿态、停留与经过的区别、可打断点、循环边界或后继状态。
- **不变量**：身份、比例、衣装结构、道具形状、镜头和格尺寸；动作允许改变的部分另列。
- **输出**：姿态图、透明逐帧、图集、预览，或接入现有运行时；按任务选择。

用户已认可骨骼、要求先以少量完整生图验证姿态时，读[骨架关键姿态小样与配准](skeleton-keyframe-proof.md)，先锁定解剖左右、画面左右与近远遮挡，再生成和审阅。

关键姿态按语义选，不从固定帧数倒推动作。先让少量完整姿态说明动作，再在缺少运动信息的区间补真实新姿态。重复图片只算停留，不算新增动作帧。

## 关键姿态、接触和配准

默认每帧绘制完整角色，保留肩、肘、腕、手掌到道具的关系。已有合格骨骼、网格权重与关节约束时可用真实 rig；不要把双臂和道具切成一整块绕胸口旋转。

| 场景 | 配准依据 | 允许的变化 |
| --- | --- | --- |
| 站立做事 | 当前承重足/身体接地位置、稳定镜头；眼部可辅助检查漂移 | 自然重心转移、头转、呼吸；不是全身像素锁死 |
| 原地走跑 | 地面基线、骨盆/躯干运动包络、每只脚的支撑阶段 | 支撑脚向后经过地面，摆动脚抬起前移；不能同时锁死双脚 |
| 带位移走跑 | 世界地面与接触轨迹，加明确根位移 | 接地脚在接触期间相对世界稳定，角色整体前进 |
| 跳跃/腾空/漂浮 | 重心、根轨迹或场景指定的悬浮点 | 不强行把空中脚底压回地面；落地后恢复接触约束 |
| 趴卧/打盹 | 腹部、臀部、爪或尾部的真实接触区 | 胸腹起伏、耳尾轻动；不让整个角色缩放后离地 |
| 攻击/闪避 | 动作根轨迹与各阶段承重关系 | 跨步、扭转、蹬地、空中动作；允许有意的大幅位移 |

统一画布与镜头尺度。不要逐帧按透明包围盒拉满格子：道具伸远或尾巴摆动会把身体缩放、左右漂移。用角色适用的固定解剖比例和分阶段锚点配准；帧间锚点变化应有动作原因。不要把裁脸、贴脚、替换头部当成常规配准。

刚性道具保持结构连贯。握持期间，道具经过手掌的位置跟随手腕与手指；需要滑杆、换手、放开时明确画出过程。扫帚杆、剑刃、杯沿不能用局部形变补关节错误。道具与头身的前后遮挡应符合镜头，不可无故穿透、消失或换层。

## 日常与萌宠动作

| 需求 | 关键姿态与接触 | 节奏检查 |
| --- | --- | --- |
| 喝水 | 取杯/靠近水面 → 接触嘴部 → 饮用 → 放回/离开；杯、嘴、手或前爪接触连续 | 喝水处可有停留；不能只把杯子移到脸旁；杯中液面/倾角随动作合理变化 |
| 打盹 | 困倦低头 → 卧下/伏下 → 安睡呼吸 → 可选惊醒/抬头 | 安睡可慢循环，睡着与醒来通常是独立过渡；呼吸不等于全身上下弹跳 |
| 趴着起身并招呼 | 抬头 → 前肢撑地 → 后躯跟上 → 重心稳定 → 空出一手/爪挥动 → 收回 | 不把趴卧和站立直接切换；挥手时保留其他支撑，朝向玩家有眼神或头部配合 |
| 扫地/擦拭 | 准备 → 扫过/擦过 → 换向 → 回程，手与道具共同运动 | 中位是经过点，避免两张近似中位叠出停顿；两端可停，但不自动套用固定时长 |
| 办妥/递交 | 接住/提起物品 → 展示或递出 → 点头/回收 | 玩家能看见结果；循环预览不代表业务重复完成 |
| 任意新动作 | 先说明目标、支撑和交互对象，再选能读懂的关键姿态 | 动作形容词应转成可见变化，例如“开心”对应耳、眼、躯干或尾巴的表现 |

不要要求所有宠物像人一样拿杯或挥手。四足可用抬前爪、点头或尾巴回应；无足角色可转向、倾身或伸出其本来具有的附肢。拟人化程度遵循设定。

## 移动与方向

- **两足**：接触、下沉/承重、经过、抬升，再换腿；走与跑的支撑结构不同，跑步可有腾空阶段。根据速度和比例选帧，不能以拉快走路冒充跑步。
- **四足**：先确定步态及前后肢相位，如漫步、小跑、奔跑；逐帧检查支撑组合、背部起伏和前后足不会互换。尾巴的跟随不能带动躯干意外漂移。
- **无足**：明确推进机制，滑行、滚动、游动、振翅、波动或悬浮；锚点和周期取自该机制，不添加不存在的脚步约束。
- **原地与带位移**：二选一作为当前权威。运行时已经推动角色时，图像不再额外横移同一段距离。漂移检查应在最终运动模型下做。
- **方向**：按项目需要选朝向数量。方向表记录镜头、前后遮挡和左右手身份；不默认横向翻转非对称衣装、持械手、伤疤或文字。向后视角需有可信的背面结构。

先验证代表性的正/侧/背方向与关键动作，再扩展全部方向；单张侧面参考不能证明背面设计已获认可。

## 主角战斗

把攻击拆为可辨认的蓄力、出招、接触/释放、随动和收招；轻重击、施法、远程和连招各有自己的节奏。检查武器握点、肩髋扭转、承重、刃/弹道方向，以及收招是否能进入下一姿态。

- 受击来自明确方向，作用部位和反应一致；受击、硬直、倒地、起身按需要分开。
- 闪避有准备、离开危险区域、恢复；无敌窗等业务窗口只在项目明确需要时声明。
- 连招、受击打断和闪避取消应与既有状态机约定衔接。一次性动作结束后不得闪回错误方向或错误握持姿态。
- 动画可以声明 `contact`、`release`、`footstep`、`attack-active` 等语义事件或时间窗。命名遵循项目协议；事件声明本身不发伤害、不改库存、不结算奖励。伤害判定仍由游戏规则所有者执行。
- 图片里的剑光、投射物或残影是表现素材。若引擎已有独立特效/弹体，明确是否拆层，避免重复出现；有意的残影不要误判为抠图残渣。

## 状态过渡与复用

为实际相邻状态设计接缝，例如待机→走、走→停、趴卧→站立→招呼、攻击→收招→待机。比较上一段最后姿态和下一段首姿态的朝向、重心、支撑和握持；需要过渡时补完整姿态，不靠淡化叠出重影。

循环末尾与开头是相邻帧，同样检查接触与速度。调整时先定位是缺姿态、近似姿态重复、停留过长还是播放顺序错误，再选择补帧、删重复或改时长。不要用增加同图次数掩盖缺少右扫等真实姿态。

换装保持同一身份、动作阶段、镜头和接触语义；衣摆与背包可有相应跟随，但不可改变四肢数量、握点或角色比例。换身份时复用动作意图、阶段与验证方法，重新适配新物种的结构、幅度与节奏，不硬套旧角色像素位置或骨骼长度。

在实际显示尺寸连续观看至少一个完整循环/过渡，也放大查关节、边缘和道具。静态拼图可查结构，不能替代对节奏、脚滑、突然停顿和循环接缝的动态检查。
